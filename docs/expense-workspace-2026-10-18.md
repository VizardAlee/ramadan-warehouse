# Operating expense workspace candidate

Base: verified live `307bf07b8b93a22df191bceb8f6f17c00b120d5a`. This is a review candidate; publication and production deployment require separate approval.

The expense register has All bills, Drafts, Needs approval, Ready to pay (approved or partially paid), and Paid history queues. It shows saved states, not inferred payment success. Draft and submitted bills are explicitly unposted/unpaid. Details retain the saved bill date, supplier-document reference, due date and recorded creator/submitter/approver IDs. No person-directory access, historical names or responsibility assignments are inferred.

Text search matches a case-insensitive NFKC-normalized substring in expense number, payee, category, supplier document number, description or linked-record label. Bill-date bounds are inclusive ISO calendar dates, not cash-payment dates. Changing filters or permitted context starts at the first page. The interface requests 25 matching rows; the existing backend 1–200 result bound is retained. Each request scans at most 500 authorized-scope records plus one lookahead (unfiltered pages read only the requested page plus lookahead). An empty filtered page may have Next. First/Previous/Next use stable document-ID order. Neither latest-first sorting nor global counts/totals is claimed.

The opaque cursor is bound to organization, actor, explicit branch/warehouse scope, normalized filters and page size. It is a navigation contract, not an authorization mechanism or database snapshot. Every request still derives access on the server, requires expenses.read at the requested scope, and checks returned record scope. Concurrent insertions or state changes can alter results between pages; refresh/restart when reconciling a changing register. Filtered search remains proportional to scanned scope membership, with bounded work per request.

Active categories, stores, warehouses and banks have continued choice pages (200 categories / 100 other choices, plus lookahead), including empty location-choice pages when no scanned locations are assigned. Existing metadata authority is retained. Previously loaded choices survive register navigation; Refresh reloads choices. Bank/card expense payment offers only configured accounts owned by the bill's store or company-wide accounts, matching the existing server settlement check. Organization/warehouse bills require company-wide accounts. The separate provider-funds workspace retains its existing controls and account inputs.

Creation shows an exact minor-unit net + VAT = gross preview and explains prerequisites. Actual writes, permission checks, maker/checker rules, closed periods, provider-obligation controls, bank settlement, idempotency, journals and audit posting are unchanged. The top-level same-tab saved-instruction owner and exact retry payload remain outside register queue/filter changes. No new expense edit, reject, cancel, reversal, file upload, approval authority or bank transfer initiation is added.

The read query catalog explicitly includes document-ID paging and all dynamic active-choice collections. A refreshed query baseline may only be generated from a successful genuine read-only planner audit of this exact query source. No rules, index manifest, IAM, credentials, secrets, App Check or production business records are changed by this candidate.
